| 期望能力 | 说明 |

## 二、V1 通信方式决策（方案A：USB 直连）

V1 阶段 HC-12 模块尚未接线，近场同步有两条路径：

| 方案 | 需要购买 | 通信方式 | 后台能力 | 成本 |
| --- | --- | --- | --- | --- |
| **方案A：USB 直连 ✅已选定** | ❌ 不需要 | 笔记本 USB 线直连 ESP32 | 读取 SD 卡日志、上传音频、查看状态 | ¥0 |
| 方案B：HC-12 无线 | 需 1 个 HC-12 + USB 转 TTL | 无线，距离 ~1km | 同上 | ~¥30 |

选定理由：

1. 现有硬件即可运行，无需等待配件；
2. 巡检时打开设备箱，USB 连上笔记本，Web 后台自动同步；
3. 功能与方案B完全一致，仅有线/无线之差；
4. V2 阶段再升级为 HC-12 无线同步（后续可选 4G 模块如 SIM7600 实现远程实时）。

技术实现链路：

```
笔记本浏览器 → 本地Web服务（localhost:5173 前端 / 8000 后端）→ USB串口 → ESP32
```

- 不需要服务器、不需要域名、不需要联网。

## 五、数据库设计（SQLite DDL）

```sql
-- 触发事件记录
CREATE TABLE trigger_events (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    event_time DATETIME NOT NULL,          -- 触发时间
    sensor_id VARCHAR(10) NOT NULL,        -- 传感器编号(SR501_1/2/3)
    audio_file VARCHAR(255),               -- 播放的音频文件名
    temperature REAL,                      -- 触发时温度
    humidity REAL,                         -- 触发时湿度
    battery_voltage REAL,                  -- 触发时电池电压
    synced_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 音频文件管理
CREATE TABLE audio_files (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    filename VARCHAR(255) NOT NULL,        -- 文件名
    category VARCHAR(50),                  -- 分类(通用驱赶/鸟类/兽类...)
    duration_seconds INTEGER,              -- 时长
    file_size INTEGER,                     -- 文件大小
    status VARCHAR(20) DEFAULT 'local',    -- local/synced/deleted
    uploaded_at DATETIME DEFAULT CURRENT_TIMESTAMP
);

-- 设备配置
CREATE TABLE device_config (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    config_key VARCHAR(100) UNIQUE NOT NULL,
    config_value TEXT,
    updated_at DATETIME DEFAULT CURRENT_TIMESTAMP
    -- 默认配置：音量、触发间隔、定时播放开关、定时播放间隔
);

-- 设备状态快照
CREATE TABLE device_status (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    reported_at DATETIME NOT NULL,
    battery_voltage REAL,
    sd_card_total_mb INTEGER,
    sd_card_used_mb INTEGER,
    uptime_seconds INTEGER,
    temperature REAL,
    humidity REAL
);

-- AI分析记录（预留）
CREATE TABLE ai_analysis (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    event_id INTEGER REFERENCES trigger_events(id),
    ai_model VARCHAR(100),                 -- 模型名称
    analysis_result TEXT,                  -- JSON格式结果
    confidence REAL,
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

默认配置项（`device_config` 初始化数据）：

## 六、通信协议设计（笔记本 ↔ ESP32，USB 串口）

所有指令和响应均为 JSON 格式，以 `\n` 分隔；波特率 115200。

```
# 同步触发日志
笔记本发送: {"cmd":"sync_logs", "since":"2025-10-01T00:00:00"}
ESP32响应:  {"status":"ok","logs":[{...},{...}]}

# 上传音频文件
笔记本发送: {"cmd":"upload_audio", "filename":"wild_boar_01.wav", "size":102400}
ESP32响应:  {"status":"ready"}
笔记本发送: <二进制数据流>
ESP32响应:  {"status":"ok","filename":"wild_boar_01.wav"}

# 拉取设备状态
笔记本发送: {"cmd":"get_status"}
ESP32响应:  {"status":"ok","battery":3.7,"sd_total":32256,"sd_used":1024,"uptime":3600,"temp":25.5,"humidity":60}

# 更新配置
笔记本发送: {"cmd":"set_config","key":"volume","value":80}
ESP32响应:  {"status":"ok"}
```

指令全集（`core/protocol.py`）：

| 指令 | 含义 |
| --- | --- |
| sync_logs | 同步触发日志（支持 since 增量） |
| get_status | 获取设备状态 |
| upload_audio | 上传音频文件到 SD 卡 |
| delete_audio | 删除 SD 卡音频文件 |
| list_audio | 列出 SD 卡音频文件 |
| set_config | 更新配置 |
| get_config | 读取配置 |

ESP32 上报触发事件 JSON 格式：

```json
{
    "event_time": "2025-10-09T14:30:00",
    "sensor_id": "SR501_1",
    "audio_file": "general_deterrent_01.wav",
    "temperature": 25.5,
    "humidity": 60.2,
    "battery_voltage": 3.72
}
```

ESP32 设备状态 JSON 格式：

```json
{
    "status": "ok",
    "battery_voltage": 3.72,
    "sd_total_mb": 32256,
    "sd_used_mb": 1024,
    "uptime_seconds": 3600,
    "temperature": 25.5,
    "humidity": 60.2,
    "free_heap": 250000
}
```

> ⚠️ 关键依赖：ESP32 固件需增加串口协议响应代码（监听串口、解析 JSON 指令、按协议应答），已确认固件可配合修改。
